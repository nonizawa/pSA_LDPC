# Bit-Aligned Temporal Reinforcement in Probabilistic-Bit Dynamics for Robust LDPC Decoding

Reproducibility package for the manuscript of the same title by Naoya Onizawa, Research Institute of Electrical Communication, Tohoku University.

**Manuscript status:** prepared for submission to *Physical Review Applied*; not yet accepted or published. The package is publicly available at [nonizawa/pSA_LDPC](https://github.com/nonizawa/pSA_LDPC). Metadata are prepared for the planned `v1.0.0` release; the formal release and Zenodo deposit remain pending. No archive DOI has been assigned.

## Overview

The primary workload is random-regular (3,6) LDPC decoding with parallel Jacobi-type p-bit updates and stochastic partial activation. The additive rule retains each bit's real-valued saturated response and reinjects it into the same bit's response path. The package supports:

- independently optimized representative-code benchmarks for pSA, additive $\lambda$-pSA, and finite-response $\tau$-pSA;
- matched causal controls for gain, normalization, and bit identity;
- response-alignment, acquisition, and post-acquisition stability analyses;
- a same-bit binary-state self-feedback control;
- package-level pSA-specific fixed transfer and a separate matched $\lambda=0$ rule ablation across 30 code realizations;
- initialization robustness under all-zero, random, and channel-hard-decision starts;
- conventional sum-product BP reference decoding; and
- MAX-CUT and matched-$k_w$ random 2-SAT boundary controls.

The package keeps four estimands separate: independently optimized representative performance, complete-package fixed transfer, matched response-rule ablation, and matched-parameter mechanism analysis.

## Quick start

```bash
git clone https://github.com/nonizawa/pSA_LDPC.git
cd pSA_LDPC
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/run_validation.py
python scripts/reproduce_figures.py
```

The validation and plotting commands do not run the full Monte Carlo studies. They exercise update-rule limits, instance identity, current numerical records, and figure generation from processed data.

For small execution checks:

```bash
python scripts/reproduce_ldpc_benchmark.py
python scripts/reproduce_matched_controls.py
python scripts/reproduce_trajectory_analysis.py
python scripts/reproduce_acquisition_stability.py
```

These use smoke-sized workloads and are not estimates of the manuscript statistics.

## Reproduction levels

### Level 1: plot-only

`python scripts/reproduce_figures.py` rebuilds the data-derived main and Supplemental figures from included CSV files. The rule schematic is a LaTeX/TikZ source at `figures/reference_current/supplement/Fig1_update_rules.tex` and is not regenerated by the Python plotting command.

### Level 2: smoke simulation

The `scripts/reproduce_*.py` entry points run low-cost execution checks for the representative LDPC kernel, matched controls, trajectories, acquisition/stability, cross-code transfer, MAX-CUT, and random 2-SAT. Outputs are written under `outputs/`, which is ignored by Git.

### Level 3: full study

The exact selected packages, search records, study drivers, seeds, matrices, and processed outputs are included. Full search, 10,000-trial evaluations, cross-code runs, and trajectory campaigns are computationally expensive and are not launched by default. Protocols and source-to-output relationships are documented in [docs/STUDY_DESIGN.md](docs/STUDY_DESIGN.md), [docs/REPRODUCIBILITY_MAP.md](docs/REPRODUCIBILITY_MAP.md), and [docs/FULL_REPRODUCTION.md](docs/FULL_REPRODUCTION.md). Full runs were not repeated during release preparation.

## BP reference

The BP curve uses the included custom NumPy binary sum-product implementation (`src/ldpc/auto_match_bp.py` and `src/ldpc/ldpc_pbit.py`): flooding updates, at most 50 iterations, zero-syndrome early termination, clipped messages, and no external decoding library. BP is a conventional decoding reference, not a claim of computational, latency, energy, or hardware superiority.

## Randomness and instance identity

Paired LDPC stochastic streams use base seed 20260826 and stride 8022 where specified. Matrix-generation seeds, C00--C09 identities, GF(2) ranks, degree checks, and SHA-256 hashes are in `data/metadata/matrices/`. Random 2-SAT formula identities, satisfiability labels, generation seeds, and hashes are in `data/metadata/formulas/`.

## Computational requirements

The primary recorded environment used Python 3.10.7, NumPy 2.2.6, SciPy 1.15.3, Matplotlib 3.10.9, Numba 0.65.1, llvmlite 0.47.0, Optuna 4.8.0, Pillow 12.2.0, and PyYAML 6.0.3. NetworkX 2.8.6 is required by the optional structural MAX-CUT generator and was available in the source host's general Python environment. Simulations are CPU-only; Numba compilation state and core count materially affect run time.

Recorded source-host wall times include approximately 3.1 h for the three matched high-statistics confirmations combined, 9.8 min for 9,000 response-alignment trajectories, 82.7 min for matched cross-code transfer, and about 36 min for the matched-$k_w$ 2-SAT grid. Full representative parameter searches and 10,000-trial evaluations are substantially heavier than the quick-start checks.

## Data policy

GitHub contains source code, configs, matrices/formulas, complete representative search records, compact raw/count data, processed trajectory summaries, validation records, and figure inputs. Large trajectory archives that are unnecessary for figure regeneration are intentionally excluded from the GitHub staging copy and listed in [ZENODO_ARCHIVE_PLAN.md](ZENODO_ARCHIVE_PLAN.md). No source data were deleted from the research workspace.
