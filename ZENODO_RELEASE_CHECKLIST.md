# Zenodo release checklist

- [ ] Make the reviewed GitHub repository public.
- [ ] Add the selected software and data/documentation licenses.
- [ ] Create and push the final manuscript-linked tag (candidate: `v1.0.0`).
- [ ] Enable the repository in the author's Zenodo GitHub integration.
- [ ] Create a Zenodo archive from the tagged GitHub release.
- [ ] Decide whether the excluded large trajectory collections will be a second
      Zenodo record or additional files in the same record.
- [ ] Verify title, author name, affiliation, description, keywords, and related
      identifiers before publishing the record.
- [ ] Publish the Zenodo record and verify the DOI resolves to the immutable
      release contents.
- [ ] Add the DOI badge/metadata to GitHub and update `CITATION.cff`.
- [ ] Insert the verified GitHub URL, release tag, and Zenodo DOI into the
      manuscript Data Availability Statement.
- [ ] Regenerate checksums and retain the final release manifest.

This staging work did not access Zenodo, upload files, mint a DOI, or create a
GitHub release.
